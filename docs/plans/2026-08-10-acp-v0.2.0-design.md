# ACP v0.2.0 Release Design

**Date:** 2026-08-10

**Goal:** Publish ACP v0.2.0 from the clean ACP main baseline with a fully tagged, vendored, and verified published dependency graph.

## Context

ACP starts at `e7b90891d0ee53fdf31afbb0a4f98fe75c6d729b`, with no local or remote `v0.2.0` tag. The release prerequisites are present remotely: Core `v0.5.0`, Harness `v0.22.0`, Inference `v0.9.0`, and Storage `v0.3.1`. The parent Looprig workspace is intentionally dirty, so release edits must stay inside a temporary ACP worktree.

## Design

Create a temporary ACP worktree from ACP `main` and make the release there. Update the module graph to use the four published versions, with Core `v0.5.0` selected as the compatible Core required by Harness `v0.22.0`. Run module maintenance with `GOWORK=off`, regenerate `vendor/` when present, and verify the selected modules are downloaded from published versions without local `replace` directives.

If the published graph exposes an API incompatibility, add a narrowly scoped regression test first, then make the smallest compatibility change needed to restore the existing contract. Do not add dependencies, change the parent `go.work`, or alter unrelated ACP worktrees.

Validation covers the requested client, launch, and protocol tests; selector/steering/model/effort/restore focused tests; default race tests; integration tests; boundary checks; vet; staticcheck; gosec; govulncheck; module verification; native and cross-platform builds; and vendor-diff review. Each network-sensitive or expensive class uses a fresh cache.

After all gates pass, commit the release changes, fast-forward ACP `main`, push `main` without force, create annotated tag `v0.2.0` without replacing any existing tag, push it, verify the branch and peeled tag refs with `git ls-remote`, and remove only the temporary release worktree.

## Alternatives considered

1. Editing ACP `main` directly is shorter, but risks mixing release work with the active parent/worktree context.
2. A detached worktree plus cherry-pick preserves the branch until the end, but adds an unnecessary manual transfer step.
3. The selected named release worktree keeps the changes isolated while allowing a checked, fast-forward integration into `main`.

## Non-goals

- No changes to the parent workspace or sibling repositories.
- No force-push, tag movement, tag deletion, or unrelated cleanup.
- No review dispatch; the requested five-task review remains deferred until Task 10.
